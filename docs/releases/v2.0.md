# GitHub Sentinel v2.0

> 第二个正式发布版本：真实数据源、真实模型、新的每日动线
> 对应标签 `v2.0`，包版本 `2.0.0`

v1.0 把「采集 → 过滤 → 摘要 → 渲染 → 通知」的全链路骨架跑通了，但除 fake 数据源之外全是占位实现：
`RestGitHub` 的四个方法直接 `NotImplementedError`，LLM 只有一个确定性的 Mock。

v2.0 把这两块补齐，并新增一条与周期简报并行的「每日动线」。

```
周期简报（tick 驱动，落库）
  tick(60s) → 抢占到期订阅 → 增量采集 → 去重入库 → 规则预压缩
            → LLM 摘要 → 渲染 HTML → 通知 → 重排下一次

每日动线（CLI / 外部 cron 驱动，落文件）
  progress → GitHub 当日 issues/pulls/commits/releases → data/daily/{YYYY}/{MM}/{slug}/{date}.md
  report   → 读上面的 md → deepseek-flash → ...-report.md（失败降级规则模板）
```

---

## 本版包含什么

### 1. 真实 GitHub REST（四资源全实现）

`RestGitHub` 从 49 行空壳补成完整实现，commits / issues / pulls / releases 全部打通：

- **`/issues` 混入 PR** —— GitHub 的 issues 端点会把 PR 当成 issue 返回，按 `pull_request` 字段丢弃。
- **分页** —— 统一走 `_paginate()`，识别 `Link: rel="next"`；同时支持 `stop_before`（早于水位就停）
  与 `skip_at_or_after`（晚于窗口就别要）两个剪枝钩子，减少无效翻页与无效解析。
- **`since` 的边界** —— `/issues` 支持 `since`，但 `/pulls` 与 `/releases` 不支持，
  只能倒序拉取后由客户端按时间截断。
- **ETag / 304** —— 命中 304 不消耗配额，也不覆盖上次结果。
- **限流退避** —— `Retry-After` 与 `X-RateLimit-Reset` 都识别，等待时长超过
  `SENTINEL_GITHUB_MAX_RETRY_WAIT` 就直接抛 `RateLimitError` 而不是干等；`sleep` 可注入，退避行为有测试覆盖。
- **错误映射** —— 401 / 403 / 404 / 429 / 5xx 映射到各自的领域异常，不把状态码漏给上层。

### 2. DeepSeek `deepseek-flash` 接入

`openai_compat` 新增自由文本生成能力（原有的结构化摘要路径保留）：

- 默认模型改为 `deepseek-flash`（`deepseek-chat` / `deepseek-reasoner` 已进入下线计划）。
- `SENTINEL_LLM_THINKING` 三态处理：`enabled` 时不发 `temperature`（两者互斥，同时发会被拒）。
- 超时按调用类型分开：摘要用 `SENTINEL_LLM_TIMEOUT`，报告用更宽松的 `SENTINEL_LLM_REPORT_TIMEOUT`。
- 报错信息带状态码 + body 前 300 字，排查不用再去翻日志。
- 构造期失败（例如没配 key）不再让整个进程起不来：按 `SENTINEL_LLM_FALLBACK_TO_MOCK` 降级到 Mock。

### 3. 每日进展 + 每日报告

新端口 `DailyStorePort` / `DailyRendererPort` / `GitHubPort.fetch_progress()`，产物按「项目 + 日期」命名：

```
data/daily/2026/11/fastapi__fastapi/
├─ 2026-11-23.md          # 每日进展：front matter + 统计表 + 议题/PR 明细表
└─ 2026-11-23-report.md   # 每日报告：一句话结论 / 关键进展 / 风险与阻塞 / 下步计划 + 附录
```

命令：

```bash
sentinel.cli progress --repo fastapi/fastapi              # 只访问 GitHub
sentinel.cli report   --repo fastapi/fastapi --date D     # 只调模型
sentinel.cli daily    --id 1 --force                      # 两步连着跑
```

几个刻意的取舍：

- **不复用 `events` 表**。每日进展是「某一天的对象清单」，不是事件流；塞进 `events` 会污染
  cron 窗口与去重键语义。所以另开端口、另落文件，每日动线不写数据库、不进 tick 调度。
- **统计数字由代码算，模型只写文字**。`domain/progress.py` 负责计数、亮点排序（`rank_highlights`）、
  风险识别（`detect_risks`），模型不参与任何计数，避免幻觉数字。
- **四章节由代码校验**。模型输出必须包含四个章节，缺一节就判定失败，退回规则模板
  （`daily_report_fallback.md.j2`），报告文件一定存在，且 front matter 标 `degraded: true` /
  `model: rules-fallback`。
- **双指纹幂等**。进展头记内容指纹，同日同数据重跑不重写；报告头记 `source_fingerprint` +
  `source_sha256`，两者都对得上、且上次不是降级产物，才跳过模型调用（`--force` 强制重跑）。

### 4. 顺手修掉的一个 v1.0 缺陷

`DigestSummary.is_empty` 写成了 `return bool(...)`，语义完全反转：只要模型返回了任何内容就被判成「空」，
于是每次真实调用都被静默丢掉、降级到 Mock。因为 `openai_compat` 此前没有任何测试覆盖，这个 bug
在 v1.0 里一直没暴露。现已修正为真正判空，并补了回归用例。

## 架构变化

分层规则不变，`ports` 仍然禁止任何第三方包、`domain` 只允许 pydantic，由
`scripts/check_layers.py` 与 `tests/unit/test_architecture.py` 双重强制。

v2.0 有一处必须遵守的推论：`CompletionRequest` / `CompletionResult` 与报告提示词只能放在
`domain/`——放 `ports/` 会违反「无第三方包」，放 `infrastructure/` 则 `application/` 无法引用
（application 不能 import infrastructure）。这也是 `infrastructure/llm/prompts.py` 里
只留摘要提示词、报告提示词移到 `domain/report.py` 的原因。

| 目录 | v2.0 新增 |
|---|---|
| `domain/` | `progress` / `report` / `completion` / `frontmatter` |
| `ports/` | `daily`（`DailyStorePort`）+ `github.fetch_progress` + `llm.complete` + `renderer.DailyRendererPort` |
| `application/` | `daily_progress_service` / `daily_report_service` |
| `infrastructure/` | `github/mapping`、`rendering/daily_store`、`rendering/daily_renderer`、`llm/openai_compat.complete` |
| `templates/` | `daily_progress.md.j2` / `daily_report.md.j2` / `daily_report_fallback.md.j2` |

## 配置新增

| 变量 | 默认 | 说明 |
|---|---|---|
| `SENTINEL_LLM_MODEL` | `deepseek-flash` | 默认模型 |
| `SENTINEL_LLM_THINKING` | `disabled` | `enabled` 时不发 `temperature` |
| `SENTINEL_LLM_JSON_MODE` | `true` | 摘要路径强制 JSON 输出 |
| `SENTINEL_LLM_REPORT_TIMEOUT` | `120` | 报告生成超时（秒） |
| `SENTINEL_GITHUB_RETRY_ATTEMPTS` | `3` | GitHub 重试次数 |
| `SENTINEL_GITHUB_MAX_RETRY_WAIT` | `60` | 超过则直接抛 `RateLimitError` |
| `SENTINEL_DAILY_DIR` | 空（= `data/daily`） | 每日产物根目录 |
| `SENTINEL_DAILY_TIMEZONE` | 空（= `SENTINEL_TIMEZONE`） | 每日窗口所用时区 |
| `SENTINEL_DAILY_RESOURCES` | `issues,pulls` | 采集哪些资源；加上 `commits,releases` 才会多渲染两节 |
| `SENTINEL_DAILY_MAX_ITEMS_PER_RESOURCE` | `200` | 单资源上限，超出标 `truncated` |
| `SENTINEL_REPORT_MAX_INPUT_CHARS` | `24000` | 报告输入上限，超出按行截断 |

`.env.example` 已同步。

## 已知限制

- **`--date` 回溯不是历史快照**。查询口径是「当前 `updated_at` 落在该日窗口」，窗口之后又被更新的
  对象会漏掉。默认建议只跑今天 / 昨天。
- **`replay` 模式仍未实现**，抓包回放还是 TODO。
- 每日动线不支持增量：每次都按窗口全量重取，仓库很活跃时靠 `MAX_ITEMS_PER_RESOURCE` 截断。
- SMTP 仍未做真实投递验证；`alembic` 迁移与多进程租约仍在待办。
- 看板仍只支持查看。

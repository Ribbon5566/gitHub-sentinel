# GitHub Sentinel v1.0

> 首个正式发布版本（Stage 1：全链路骨架完成）
> 对应标签 `v1.0`

自托管的 GitHub 仓库动态哨兵 —— 订阅仓库后，它会定时增量抓取 commit / issue / PR / release，
用 LLM 归纳成摘要报告，推送到邮件，并在看板里留档回看。

```
定时 tick(60s) → 抢占到期订阅 → 增量采集(GitHub REST) → 过滤去重(SQLite)
              → 规则预压缩 → LLM 摘要(失败降级 Mock) → 渲染 HTML → 通知(SMTP) → 重排下一次
```

---

## 本版包含什么

### 完整数据链路

一条命令 `sentinel.cli seed-demo` 即可跑通「采集 → 过滤 → 摘要 → 渲染 → 通知 → 重排」全流程，
无需任何外部服务或密钥，离线可验证。

### 增量采集三重保险

- **`since` 水位** —— 交给 GitHub 服务端过滤，减少无效返回
- **`ETag` / `If-None-Match`** —— 命中 304 不消耗 API 配额
- **本地唯一键** —— 兜底分页带来的重复

水位取「事件源侧时间」的最大值而非运行开始时间，并回退 90 秒防漏；只有整轮成功才推进水位，
中途失败不会把事件永久跳过。

### 双层去重键

恒定键 `(repo, kind, external_id)` 配合版本键（commit = sha、issue/PR = updated_at、release = published_at）：

- issue 被关闭、PR 被合并 → 版本键变化 → 再次播报
- 只改了个错别字 → 不产生新条目

### 单 tick 调度，重启自愈

不为每个订阅建一个 cron job（那需要与 CRUD 双向同步、重启全丢、多进程各跑一份）。
只保留一个 60 秒 interval tick，到期判定与抢占全在 SQL 里完成：

```sql
UPDATE subscriptions SET next_run_at = ... WHERE next_run_at <= now RETURNING id
```

重启后过期任务自然被重新捡起，多进程靠租约互斥。

### LLM 只负责归纳

- 先用规则把事件压缩到约 3k 字，再调模型，控制 token 成本
- 统计数字由 `domain/digest.py` 算好，模型不参与计数（避免幻觉数字）
- 输出强制 JSON 并经 pydantic 校验
- 无 Key / 超时 / 解析失败 → 自动降级到确定性 Mock，链路不断

### 报告与通知幂等

- 报告 `UNIQUE(subscription, period_start, period_end)` + `content_hash` 复用，重跑同周期不重复烧 token
- 通知幂等键 `report_id:channel:target`，重发需显式 `resend`，键后追加序号，可审计且不刷屏

## 架构

严格四层，依赖单向向内，由 `scripts/check_layers.py` 在测试中强制：

```
api → application → ports → domain
       ↑            ↑
  infrastructure ───┘     （infrastructure 只实现 ports，禁止 import application / api）
```

| 目录 | 职责 |
|---|---|
| `domain/` | 纯领域：enums / models / dedup / filters / schedule / digest / errors |
| `ports/` | 6 个 Protocol + 跨层 DTO（github / llm / notifier / renderer / clock / repositories） |
| `application/` | 用例编排：subscription / collect / digest / notify / pipeline |
| `infrastructure/` | 端口实现：github(fake, rest) / llm(mock, openai_compat) / notify(null, smtp) / persistence / rendering / scheduling |
| `api/` | FastAPI 路由 + 看板页面 |
| `container.py` | 组合根，唯一同时依赖 api 与 infrastructure 的地方 |

**扩展成本**：加企微/飞书通知 = 新增一个 `Notifier` 实现 + `notify/registry.py` 加一行；换真实 GitHub = 改一个环境变量加 token，上层零改动。

## 快速开始

```bash
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -e ".[dev]"

cp .env.example .env                       # 默认即可跑：fake 数据 + mock 摘要 + dry-run 通知
./.venv/Scripts/python.exe -m sentinel.cli seed-demo
./.venv/Scripts/python.exe -m uvicorn sentinel.main:app --port 8000 --loop asyncio
```

- 看板 <http://127.0.0.1:8000/>（Basic Auth，密码 = `SENTINEL_API_KEY`）
- API 文档 <http://127.0.0.1:8000/docs>
- 报告落盘于 `data/reports/YYYY/MM/{订阅ID}/`

常用 CLI：`seed-demo` / `subscribe owner/repo --cron "0 9 * * *"` / `collect` / `digest` / `tick --once` / `list`

## 配置矩阵

| 变量 | 可选值 | 默认 |
|---|---|---|
| `SENTINEL_GITHUB_MODE` | `fake` / `replay`(待实现) / `live` | `fake` |
| `SENTINEL_LLM_PROVIDER` | `mock` / `openai_compat` | `mock` |
| `SENTINEL_NOTIFY_CHANNEL` | `null` / `smtp` | `null` |
| `SENTINEL_API_KEY` | — | 留空则仅本机可访问 |
| `SENTINEL_ENABLE_SCHEDULER` | `true` / `false` | web 进程建议 `false`，调度交给 `sentinel.worker` |

> Windows 必须安装 `tzdata`（已在依赖中），启动需加 `--loop asyncio`，否则 `ZoneInfo("Asia/Shanghai")` 会直接抛错。

## 已知限制

- GitHub 数据源默认为内置 Fake，`live` 模式的端点映射、分页、限流退避尚未打磨
- LLM 默认 Mock，`openai_compat` 已可用但缺分块与重试细节
- 通知默认 dry-run，SMTP 尚未做真实投递验证
- 无 alembic 迁移，表结构变更需手工处理
- 看板仅支持查看，建订阅/筛选/分页待补
